# Tripo AI reference pack - Jalebi bhog game (Shreenathji / Pushtimarg)

Compiled 2026-11-11. Three sections: (1) reference images per asset, (2) Tripo AI best practices, (3) Pushtimarg bhog seva facts.

## How to read this file

**What "verified" means here.** Every image listed in Section 1 was downloaded into a fresh folder and looked at before being listed, unless the entry says otherwise. For Wikimedia Commons files the copy that was viewed is the 500 px rendition linked from the file's own page (served from `thumb.wikimedia.org`); the "Image" link given is the full-resolution original from the same page. Licence and author are copied from each file page.

**Hosts that could not be used from the research container** (so nothing from them is listed):

| Host | Result | Effect |
|---|---|---|
| pexels.com, pixabay.com | HTTP 403 from the network proxy | not searched |
| unsplash.com | "Checking your browser" bot check | not searched |
| api.openverse.org | HTTP 504 | not searched |
| metmuseum.org / collectionapi.metmuseum.org | HTTP 429 / 410 | Met images are listed only where a copy exists on Wikimedia Commons |
| flickr.com | search pages load, image host returned non-image responses | nothing verified, nothing listed |
| upload.wikimedia.org (full-size originals) | some requests refused with HTTP 429 "robot policy" | originals not downloaded; the 500 px renditions of the same files were viewed instead |
| www.tripo3d.ai (blog, help centre, product-doc) | HTTP 403 | Tripo help-centre statements in Section 2 come from search-engine summaries of those pages and are marked "(search summary)" |
| pushti-marg.net, vallabhkankroli.org | host not reachable | not used in Section 3 |

**Practical download tip for the parent.** Open the "Page" link, click *Download*, and pick a rendition of about 1024-2048 px. Tripo accepts PNG, JPEG and WebP (not TIFF). Crop to the single object, leave a small margin, and remove the background before uploading (Section 2).

**Licences.** Public domain and CC0 images need no credit. CC BY and CC BY-SA images are fine as *input references*; if a cropped photo itself is shipped in the game (for example a pichwai used as a texture) credit the author, and for BY-SA keep that image under the same licence. Whether a 3D model generated from a BY-SA photo counts as a derivative work is not something this file can settle; where it matters, prefer the PD / CC0 options, which are flagged.

## 1. Reference images per asset

### 1. Shreenathji swaroop

Best input is still the family's own chitraji or a photo of their own sevya swaroop: it will match the shringar they know, and there is no licence question. Photograph it straight-on, whole figure in frame, even light, no glass reflections. The swaroop at Nathdwara is itself a bas-relief in black stone, so a flat-backed model (or even a textured upright card) is true to the original. Of the images below, only the first is a photograph of a three-dimensional murti; the rest are paintings, which Tripo will turn into a relief-like figure.
- **Shreenathji USA.JPG**
  - Image: <https://upload.wikimedia.org/wikipedia/commons/e/e1/Shreenathji_USA.JPG>
  - Page: <https://commons.wikimedia.org/wiki/File:Shreenathji_USA.JPG>
  - Licence / author: Public domain / Lalbal
  - Why: Photograph of a real 3D black murti, front-facing, full figure, left arm raised and right fist on hip, plain floor. The only free photo found of the form in the round.
  - Note: This murti is in a Swaminarayan temple (Colonia, New Jersey) and wears a paag and yellow dhoti, not Nathdwara shringar. Remove the carved-door background before upload.
- **Sri Nathaji, c. 1900 - Cleveland Museum of Art 2001.162**
  - Image: <https://openaccess-cdn.clevelandart.org/2001.162/2001.162_web.jpg>
  - Page: <https://clevelandart.org/art/2001.162>
  - Licence / author: CC0 (museum open access) / unknown Nathdwara painter
  - Why: Shows the black stone swaroop itself with almost no shringar: raised left arm, right fist on hip holding lotus and stick, large eyes, the arched stone slab behind. Clearest silhouette of the body.
  - Note: Painting, 620x900 at web size; the museum page offers a larger download.
- **Shrinathji Vitthalanath Birthday Shringar.jpg**
  - Image: <https://upload.wikimedia.org/wikipedia/commons/2/2e/Shrinathji_Vitthalanath_Birthday_Shringar.jpg>

  - Why: High-resolution Nathdwara painting, single full figure, front-facing, with mukut, mor-pankh and wide yellow ghera vastra. Good for the dressed look and for colours.
  - Note: Painting with a decorative border; crop to the figure.
- **Sri nathji.jpg**
  - Image: <https://upload.wikimedia.org/wikipedia/commons/f/ff/Sri_nathji.jpg>
  - Page: <https://commons.wikimedia.org/wiki/File:Sri_nathji.jpg>

## 2. Tripo AI best practices

**Source labels used below**

- **[API]** - Tripo's current developer docs at developers.tripo3d.com. Official; each page cited was fetched.
- **[API-legacy]** - Tripo's older OpenAPI docs at docs.tripo3d.ai. Official; fetched.
- The fetch tool returns a summary of the page rather than its raw text, so parameter names, defaults and limits below are as that tool reported them, and quoted phrases may be lightly condensed. Check the linked page before hard-coding a number.
- **[Help, search summary]** - Tripo's own help centre, product-doc or blog on www.tripo3d.ai. Official, but the site returned HTTP 403 to the research container, so the wording comes from search-engine summaries of those pages, not from reading them. Check these against the page before relying on a number.
- **[Three.js]** - threejs.org docs, fetched the same way.
- **[Mine]** - my own recommendation for this game; not a Tripo statement.

The API docs describe the same engine the Tripo Studio web app uses, but the app's buttons are named differently. Where the Studio name is known it is given; where it is not, that is said.

### 2.1 Ideal input image

| Property | Guidance | Source |
|---|---|---|
| File type and size | PNG, JPEG or WebP, up to 20 MB | [API] <https://developers.tripo3d.com/en/docs/generation-image-to-model/standard> |
| Resolution | API minimum recommendation is 256 x 256 px. The help centre says aim for 1024 x 1024 or larger, and that below roughly 512 x 512 there is too little information | [API] same page; [Help, search summary] <https://www.tripo3d.ai/help/features/how-to-check-the-image-to-3d-input-quality> |
| Content | "The subject should be clearly visible with a clean background and minimal occlusion" (as summarised from the API page) | [API] same page |
| Background | Plain white or grey; remove a busy background before uploading | [Help, search summary] same help page |
| Framing | Subject fills about 70-90% of the frame with a small margin on every edge; a subject touching the edge tends to come out cropped | [Help, search summary] same help page |
| Angle | Front-facing or slightly angled (3/4); avoid steep top-down or bottom-up shots | [Help, search summary] same help page |
| Lighting | Even, diffused light; hard directional light bakes shadows into the texture. Studio has a "Remove Lighting" toggle, and the API has `delight` (default on) | [Help, search summary] same help page and <https://www.tripo3d.ai/product-doc/module-post-processing/texture-pbr>; [API] image-to-model page |
| Low-quality input | API option `enable_image_autofix` (default off) enhances low-resolution or poor images first. Useful for the small files in Section 1 (Kadai.jpg, Sri nathji.jpg, LACMA lota) | [API] image-to-model page |
| One object | Not stated as a rule in the pages I could read, but every guide assumes a single subject; crop multi-object photos to one object | [Mine], consistent with the above |

One Tripo blog post argues for directional light instead of diffuse light; the help-centre pages side with even light. That conflict was reported by the search summary and I could not read either page.

### 2.2 When to use multi-view

- Accepts up to four views: front, left, back, right. "The front view cannot be omitted." "You may omit other views, but at least 2 images are required." "All images should depict the same object under consistent lighting." [API] <https://developers.tripo3d.com/en/docs/generation-multiview-to-model/standard>
- Use it when the object is asymmetrical, when the sides or back carry important detail, or when a front image cannot describe the whole volume. A single image is usually enough for symmetrical, simple objects. [Help, search summary] <https://www.tripo3d.ai/help/features/how-to-get-better-image-to-3d-results-with-tripo-ai>
- Mixing photos from different sessions, lighting or scale causes seams. [Help, search summary] same page.
- [Mine] For this game: single image for jalebi, kadhai, katori, lota, pattal, tokri, cymbals, bell (all round or symmetrical). Multi-view for the chulha (fire mouth on one side only - use "Clay stove 01-04"), the pateela with lid, the pakhawaj (two different drum heads), and Shreenathji if the family can photograph their swaroop from the front and both sides.

### 2.3 Text-to-3D prompt tips

- Prompt up to 1024 characters: "Describe shape, material, style, and scale." Negative prompt up to 255 characters. Good example given: "A low-poly medieval wooden treasure chest with iron hinges and a rusty lock." Bad example: "A box." [API] <https://developers.tripo3d.com/en/docs/generation-text-to-model/standard>
- Order the prompt as subject, then details/materials, then style; keep to one subject; prefer concrete surface words ("pitted cast iron") over quality adjectives ("highly detailed"). [Help, search summary] <https://www.tripo3d.ai/help/features/tripo-ai-prompt-guide-best-practices-and-templates-for-3d-models>
- For characters that will be rigged, ask for a T-pose or A-pose explicitly; keep accessories few and attached. [Help, search summary] same page.
- There is no separate style field in the current API; style is written into the prompt. [API] text-to-model page.

### 2.4 Settings for light, mobile-friendly models

What Tripo offers:

- **Two model families.** H series is the high-precision line; P series is for "Game pipelines / UGC generative gameplay / Mobile 3D assets" (P1) and "Game characters and props ... Real-time production pipelines" (P2), with "cleaner topology and more precise face-count control". P1 allows 50-20,000 faces; P2 allows 48-50,000 triangles or 48-25,000 quads. [API] <https://developers.tripo3d.com/en/docs/models-and-versions>
- **Studio names.** In Tripo Studio the two paths are labelled "Best Quality = HD Model = H Series" and "Clean Topology = Smart Mesh = P Series"; Smart Mesh polycount 500-50,000, default 10,000. [Help, search summary] <https://www.tripo3d.ai/product-doc/model-generation/image-to-3d>
- **Face limit.** `face_limit` caps the polygon count; if omitted it is adaptive. On the P series "simple models start at 150 faces; complex models at 250", and lower values may hurt quality. [API] <https://developers.tripo3d.com/en/docs/generation-image-to-model/p>
- **Smart low poly (H series).** `smart_low_poly: true` "generates low-poly, clean-topology models. Best for simple inputs"; limits become 500-20,000 triangles or 500-10,000 quads. The legacy docs add that there is "a possibility of failure for complex models". [API] H-series image-to-model page; [API-legacy] <https://docs.tripo3d.ai/model-generation/image-to-model-v3-0-v3-1.html>
- **Quad vs triangle.** `quad: true` outputs quads but **forces the output format to FBX**. For Three.js keep triangles so the output stays GLB. [API] H-series image-to-model page.
- **Retopology after the fact.** A separate Retopology task reduces an existing model to a `face_limit` of 500-20,000 triangles and can bake the textures onto the low-poly mesh; output is GLB. [API] <https://developers.tripo3d.com/en/docs/mesh-decimate>
- **Texture resolution.** Studio offers 2K / 4K / 8K, default 2K (2K = 2048 x 2048). [Help, search summary] <https://www.tripo3d.ai/product-doc/module-post-processing/texture-pbr>. The API calls the tiers `standard` / `detailed` / `extreme`; `extreme` is 8K at extra cost. [API]. The docs do not map the Studio labels to the API labels explicitly. The export/convert step has `texture_size` (default 4096 px) and `texture_format` (default JPEG, "smallest files"). [API] <https://developers.tripo3d.com/en/docs/models-convert>
- **PBR.** `pbr: true` (the default) adds base colour, metallic, roughness and normal maps; `pbr: false` gives a plain textured model; `texture: false` gives bare geometry. [API] P-series image-to-model page.
- **Compression.** The H-series generation call has `compress: "geometry"`, described as meshopt compression to reduce file size. [API] H-series page. A meshopt-compressed GLB will not load in Three.js unless a decoder is registered (see 2.5).
- Tripo's own blog suggests keeping textures at or under 2K for mobile GPUs. [Help, search summary] <https://www.tripo3d.ai/blog/explore/smart-mesh-export-settings-for-glb-meshes>

[Mine] Suggested settings for this game (Android, Three.js, toddler-simple look). These are starting budgets, not Tripo figures; test on the target phone:

| Asset type | Path | Face limit | Texture | PBR |
|---|---|---|---|---|
| Small props: jalebi, katori, elaichi, manjira, bell, dona, kalchhi, jhara | Smart Mesh / P series, triangles | 500-2,000 | 512-1024 px | off, or on for brass only |
| Medium props: kadhai, pateela, chulha, tokri, lota, jhari, pakhawaj, dholak, bajot | Smart Mesh / P series, triangles | 2,000-5,000 | 1024 px | on for metal, off for clay, leaf, cane |
| Shreenathji, sinhasan | Smart Mesh / P series, or H series then Retopology | 8,000-15,000 | 2048 px | on |
| Diners (four characters, visible together) | Smart Mesh / P series | 4,000-8,000 each | 1024 px each | off |

Pattal, pichwai and arch should stay flat textured quads; do not generate them as 3D.

### 2.5 Export for Three.js

- Generation tasks return a `.glb` by default (the docs' example outputs are `model_url` ending in `.glb`). Enabling quads switches the output to FBX. [API] text-to-model and image-to-model pages.
- Tripo Studio exports FBX, OBJ, GLB, USDZ, STL and 3MF; the docs recommend GLB for web and AR and FBX for Unity/Unreal. The export panel has toggles for textures, rig and animation; OBJ carries no skeleton. One help page lists USD where the product doc lists USDZ, and format availability may depend on the plan. [Help, search summary] <https://www.tripo3d.ai/product-doc/export-and-integration/export-dcc>, <https://www.tripo3d.ai/help/getting-started/what-3d-file-formats-do-you-support>
- The API convert step lists `GLTF` (not `GLB`) as its web format, alongside FBX, USDZ, OBJ, STL, 3MF. Useful options there: `face_limit`, `texture_size`, `texture_format`, `pivot_to_center_bottom` (default off), `flatten_bottom` (default off), `scale_factor`, `with_animation` (default on), `bake` (default on). [API] <https://developers.tripo3d.com/en/docs/models-convert>
- Three.js loads GLB with `GLTFLoader`. If the file uses meshopt compression, `setMeshoptDecoder` is "Required for decoding assets compressed with the EXT_meshopt_compression extension"; Draco-compressed files need `setDRACOLoader`; KTX2 textures need `setKTX2Loader`. [Three.js] <https://threejs.org/docs/pages/GLTFLoader.html>

[Mine] What to tick when exporting for this game: format GLB; triangles (not quad); textures included; bottom-centre pivot on, so every prop sits on the table or floor at y = 0; flatten bottom on for things that stand (pots, stove, stool); for characters, skeleton and animation on. Leave compression off unless the game code registers the meshopt decoder. I could not open the Studio export dialog, so the exact labels there are unconfirmed.

### 2.6 Style presets

Unclear, and the sources disagree:

- The current API has **no style parameter** on generation; style goes in the prompt. [API] text-to-model page. A post-processing stylize endpoint exists (`POST /v3/models/stylize` is listed in the migration table) but its options are not documented on any page I could read. [API] <https://developers.tripo3d.com/en/docs/migration-v2-to-v3>
- A Tripo blog post describes a style grid before generation (Cartoon, Christmas, Barbie, Clay, Steampunk, Alien) and post-generation presets (Voxel, LEGO, Voronoi, Clay), but the same post reportedly lists Clay, Voronoi, Cartoon and Realistic as "coming soon"; a newer Tripo post names only Lego, Voxel and Voronoi. [Help, search summary] <https://www.tripo3d.ai/blog/how-to-achieve-different-artistic-styles>
- Third-party: the ComfyUI node documentation describes a "Stylize model" node with styles such as Lego and clay.

Practical answer for the parent: look for a Style or Stylization control in the current Studio UI; if there is no Cartoon preset, get the look by writing "stylized cartoon, chunky toy-like proportions, flat colours" into the prompt, or by uploading a cartoon reference image.

### 2.7 Auto-rigging and animation

- **Rig check** returns `riggable` (true/false) and a recommended `rig_type`. [API] <https://developers.tripo3d.com/en/docs/animations-rig-check>
- **Auto rig** accepts a generated model or an uploaded GLB/FBX/OBJ/STL up to 150 MB. Rig types: biped, quadruped, hexapod, octopod, avian, serpentine, aquatic, others. Skeleton naming for bipeds (`spec`): tripo, mixamo, actorcore, unity, unreal, vrm. Output `out_format`: **glb (default) or fbx**. [API] <https://developers.tripo3d.com/en/docs/animations-rig>
- **Preset animations (retarget).** Output glb or fbx; `animate_in_place` option; up to 5 animations per request. On the current humanoid rig (v3.0) the biped presets are idle, walk, run, dive, climb, jump, slash, shoot, hurt, fall, turn. The older v1.0 biped rig has 90+ presets including `sit`, `clap`, `bow`, `agree`, `cheer`, `greet_01`-`04`, `wave_goodbye`, `sing`, `dance`. [API] <https://developers.tripo3d.com/en/docs/animations-retarget>
- T-pose or A-pose input gives cleaner rigs; mid-action poses are harder; props are not rig targets. [Help, search summary] <https://www.tripo3d.ai/blog/how-to-animate-an-ai-generated-3d-model>
- In Studio, FBX and GLB both carry skeleton and animation; the export panel has an "Export Skeleton" toggle and a "Number of Animations" setting, and the clip must be selected before export. [Help, search summary] <https://www.tripo3d.ai/blog/apply-preset-animations-to-3d-character>

[Mine] For this game there are two workable routes for the diners. (a) Generate each diner already seated cross-legged and leave it un-rigged; animate with simple code (bob, lean, a prasad item moving to the mouth). This is the lightest option and avoids the rigging step failing on a folded-leg pose. (b) Generate a standing T-pose character, auto-rig as biped, export GLB with skeleton, and pose the legs in code or apply a preset. I could not confirm what the `sit` preset looks like; it is probably a chair sit, not palthi, so do not count on it. Only the halwai (the player character) really needs a rig.

## 3. Pushtimarg bhog seva facts

Sources that were opened and read: a home-seva guide on pushtimarg.net; the PushtiDham (Ocala) haveli FAQ; the "Charanamrut" English FAQ PDF on archive.org; "Why Do We...?" by Hasmukh Shah on vraj.org (Vraj temple, Pennsylvania); a "How to perform nitya seva of Thakorji" post on the Vallabh Kul blog; an LSE doctoral thesis on Pushtimarg seva; and the Wikipedia articles on Shrinathji and Haveli Sangeet. These are community and devotional sources plus one academic one; none is a sampradaya-issued manual.

Practice differs between havelis and homes, so where the family's own usage differs, theirs should win.

### 3.1 The sequence

| Step the family described | Verdict | Evidence |
|---|---|---|
| Bhog dharvo - food placed before Shreenathji | Confirmed | "Before the food is offered, it is known as samagri, it is then transformed into bhog ... the remainder becomes prasad" (LSE thesis, p. 101). "Offer Dhoopdeep and then full lunch (Rajbhog) to Lord" (pushtimarg.net) |
| Parda closed while Thakorji aarogs | Confirmed in substance | "Close the door /curtain" (Vallabh Kul blog). "Two other darshans are closed: Bhog, where a meal is served to Krishna" (LSE thesis). Time allowed per pushtimarg.net: Mangal bhog 12 minutes, Gwal 24, Rajbhog 48, Utthapan 15, Shayan 24; the Vallabh Kul post says "at least for 30 minutes" |
| Kirtan sung | Confirmed | Kirtans are sung "at the time of awakening in the morning, bathing, offering shreengar & Bhog etc." (pushtimarg.net kirtan page). The seva guide names bhog-time kirtans: "Sing bhog aaye ke kirtan" |
| Parda opened (darshan), then bhog saravo | **Order differs in the written guides** | Both home-seva guides remove the bhog first and open darshan after: "Then take away all bhog items" followed by "Offer Aachman-Mukhvastra-Bida" (pushtimarg.net); "Do achamana / Mukha vastra, offer biri and remove the bhog ... After doing this open the darshan" (Vallabh Kul blog). I found no source for opening the curtain before removing the bhog |
| Bhog becomes prasad | Confirmed | "Once ShriKrishna-as-ShriNathji accepts the Bhog, it becomes Maha-Prasad / Prasad to be distributed as Bhagwan's blessings to the devotees" (vraj.org) |
| Prasad served to Vaishnavs | Confirmed in general | "take Mahaprasad for self after offering it to other devotees"; some is set aside for a cow (pushtimarg.net) |
| ... on pattal | **Not confirmed** | No source I could open mentions leaf plates for Pushtimarg prasad. Leaf-plate pangat meals are a general Indian custom (see the photos in Section 1.13), so it is plausible, but it rests on the family's account |

Sequence as the written guides give it, for the game script: bhog dharvo (with tulsi and jhari) -> door or curtain closed -> kirtan while Thakorji aarogs -> wait -> bhog saravo -> achman (water to rinse), mukhvastra (cloth to wipe), bida (paan) -> curtain opened, darshan (and aarti at the main bhogs) -> prasad shared. Ask the family whether they want their own order or this one.

### 3.2 Specific questions

**Is a tulsi leaf placed on the bhog?** Yes, with a qualification.
- "Put one-one Tulsi leaf in each item" - Rajbhog section, <https://pushtimarg.net/seva/>
- "Tulsi leaves are placed in the meals offered to ShriKrishna-as-ShriNathji" - <https://vraj.org/PDF_folder/2025/Why_Do_We_Hasmukh_Shah.pdf>
- "Tulsiji is dearest to Thakorji. She removes the dosh in Samagri and enables the Samagri to be worthy for Thakorji" - <https://www.pushtidhamocala.org/FAQ.asp>
- Separately, a *tulsidal* (two leaves on one stem) is offered at Thakorji's feet once the Rajbhog is arranged - Charanamrut FAQ, Q44, <https://archive.org/download/Pushtimarg/Charanamrutenglish.pdf>
- Qualification: the explicit instructions are for Rajbhog. A search summary of a Kankroli (third house) routine says tulsi samarpan is done only at Rajbhog and Shayan bhog; that site could not be opened, so this is unverified. Whether tulsi goes on a single-sweet bhog such as jalebi is for the family to say.

**Is a jhari of water placed alongside?** Yes.
- "Fill up Jariji by humming Shri Yamnunashtaka and keep it there" - Rajbhog section, <https://pushtimarg.net/seva/>
- "Fill jhariji and place it on the left side of Shri Thakorji on the sinhasan" - <https://vallabhakul.blogspot.com/2011/01/>
- "Jariji is to be filled 8 times a day"; "The color of Jariji's cloth is red and it is called Nevro"; the jhari is regarded as the swaroop of Yamunaji - Charanamrut FAQ Q41, Q42, Q60 (same archive.org PDF) and the PushtiDham FAQ.
- Game detail: jhari on Thakorji's left, on or beside the sinhasan, red cloth cover.

**What is the curtain called?** Not settled by the sources.
- Wikipedia uses *parda*: "The view of the icon after the parda (curtain) is removed is called jhakhi" - <https://en.wikipedia.org/wiki/Shrinathji>
- The English-language seva guides just say "curtain" or "door".
- **"Tera" / "tero" could not be confirmed**: no page I could open uses it, and searches in English, Hindi and Gujarati returned nothing. That does not make it wrong - the two sites most likely to carry a glossary (pushti-marg.net, vallabhkankroli.org) were unreachable. Use the family's word in the game, with "parda" as the safe documented alternative.

**Which instruments accompany haveli sangeet kirtan?**
- "The main musical instruments used are... Tanpura (Tambura), Pakhavaj (Mrudang), Veena, Sarangi, Flute, Khanjari, Duff, Zanz, Kinnari, Upang, Harmonium (introduced later)" - vraj.org PDF, kirtan section (around p. 70-71). "Zanz" is jhanjh.
- "Accompaniment is provided by the pakhavaj drum, the plucked stick zither (rudra veena), the sarangi ... the drone tanpura (used occasionally), and the harmonium" - <https://en.wikipedia.org/wiki/Haveli_Sangeet>, citing Gaston, *Krishna's Musicians* (1997).
- Pakhawaj: confirmed by both. Jhanjh: confirmed by the vraj.org list (and a search summary of a Skidmore College recording note describes pakhawaj with jhanjh, tambura and harmonium).
- **Manjira: not confirmed** for haveli kirtan specifically. The LSE thesis mentions hand cymbals ("kartal") in a devotees' kirtan class, so small cymbals are not out of place, but no source names manjira.
- **Dholak: not mentioned** by any source. Prefer the pakhawaj in the game.
- The two sources disagree on the flute: the vraj.org list includes it, while Wikipedia (citing Gaston) says the bansuri is left out of temple ensembles because it is reserved for Krishna. Safest to leave a flute out of the musicians' hands.

**What greeting is used?** "Jai Shri Krishna" - confirmed.
- "A way to do so is to greet a vaishnav - known or unknown - by saying 'Jai ShriKrishna' while putting our palms together in front of our heart" - vraj.org booklet, chapter 2. It accepts both "Krushna" and "Krishna" spellings.
- The LSE thesis shows it in live use: the researcher's survey for devotees opens "Jai shree Krishna", in English and in Gujarati (appendix 2).
- Two etiquette points from the vraj.org booklet that may matter for the game: Vaishnavs do **not** say "Jai ShriKrishna" to each other during darshan, in the presence of Thakorji ("This is a Vaishnav protocol"); and it is not said to a Pushtimarg guru (Goswami), who is greeted with "Dandvat Pranam". So the greeting fits the prasad-serving scene, not the moment the curtain opens.

### 3.3 Other points that affect the game

- The Nathdwara swaroop "is carved in bas-relief out of a monolithic black marble stone" (Wikipedia, Shrinathji) - supports a flat-backed model.
- The eight daily darshans are Mangla, Shringar, Gwal, Rajbhog, Utthapan, Bhog, Sandhya Aarti, Shayan (Charanamrut PDF).
- After bhog: achman, mukhvastra and bida are offered "after taking away the bhog" (Charanamrut FAQ Q68) - three small props if the game wants them.

### 3.4 Not confirmed - please check with the family

1. The word "tera / tero" for the curtain.
2. Prasad being served on pattal in Pushtimarg practice.
3. Opening the curtain before removing the bhog (written guides have the reverse).
4. Tulsi on a bhog other than Rajbhog or Shayan bhog.
5. Manjira and dholak as haveli kirtan instruments.
